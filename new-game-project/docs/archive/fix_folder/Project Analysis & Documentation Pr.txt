Architecture & Systems2.1 File Organization & StructureMaintain the following directory structure7:Plaintextscripts/
├── Core/          # Core systems (Turn system, Grid)
├── Managers/      # Singleton-like managers (PhaseManager)
├── Resources/     # Resource definitions (CharacterData)
├── Units/         # Unit logic (Solo/Duo)
├── UI/            # UI Controllers
└── scenes/        # (.tscn files)
Scene vs. Script Decision8:Use Scenes (.tscn): UI panels, Units, Visual Effects.Use Scripts (.gd): Managers, Resources, Autoloads, Pure Logic.2.2 Data-Driven Design (Resources)Do not use Dictionaries for game data. Use typed Resource classes9.Current Resources: CharacterData, CharacterClass, Weapon, SupportConversation, MapData.2.3 Communication PatternsDependency Injection: Never use get_node() paths for systems. Inject dependencies via setup() or set_dependencies() methods10.Signals: Use signals for cross-system communication. Never access nodes directly across hierarchy branches11.Key Signals: unit_health_changed, phase_changed, bond_updated.2.4 Optimization: Dirty FlagsDo not update visuals every frame in _process. Use "Dirty Flags" to update only when data changes12.GDScriptvar _state_dirty: bool = false
var state: TileState:
    set(value):
        if state != value:
            state = value
            _state_dirty = true # Flag change

func _process(_delta: float) -> void:
    if _state_dirty:
        _update_visual_state() # Update once
        _state_dirty = false

Refactoring GuideUse this guide when optimizing or cleaning existing code.5.1 Refactoring PrioritiesCritical (High): Security issues, performance bottlenecks, major duplication, missing type hints21.Architectural (Medium): Breaking up oversized files (>500 lines), improving modularization.Cleanup (Low): Code style, minor optimizations.5.2 Handling Oversized FilesIf a file exceeds 500 lines or mixes concerns (e.g., UI and Logic)22:Identify Sections: Group related functions.Extract: Move logic to a new Manager or Helper script.Delegate: The original file should call the new script's methods.5.3 Code Analysis ChecklistWhen reviewing code, look for23:High Complexity: Nested loops or excessive recursion.Duplication: Identical logic in multiple files (extract to shared module).Coupling: Tight dependencies between unrelated modules.Unused Assets: Dead variables, imports, or functions.6.
